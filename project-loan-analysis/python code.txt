def map_dpd(status):
    if status == 'Current':
        return 0
    elif status == 'In Grace Period':
        return 0
    elif status == 'Late (16-30 days)':
        return 30
    elif status == 'Late (31-120 days)':
        return 60  # simplified midpoint
    elif status == 'Default':
        return 90
    elif status == 'Charged Off':
        return 120
    else:
        return 0

df['dpd'] = df['loan_status'].apply(map_dpd)

def calc_tkb(df, threshold):
    return 1 - (df[df['dpd'] > threshold]['OS'].sum() / df['OS'].sum())

tkb0 = calc_tkb(df, 0)
tkb30 = calc_tkb(df, 30)
tkb60 = calc_tkb(df, 60)
tkb90 = calc_tkb(df, 90)

In Fintech, "Not Verified" doesn't mean we don't know who they are. It usually means the user didn't upload a payslip, but we verified them using Alternative Data (like their phone bill, e-commerce history, or bank scrapings).



The Business Logic to tell your Coach:

- Market Expansion: We accept "Not Verified" to reach the Unbanked population (freelancers/SMEs) who don't have formal payslips but have high income.

- The "Yield" Play: Look at your data—I bet the avg_rate for "Not Verified" is much higher than "Verified." We charge them more to cover the risk of them being "bad."

- Low Barrier to Entry: It makes the "Customer Journey" faster. If you require everyone to be "Verified," they might go to a competitor instead.
